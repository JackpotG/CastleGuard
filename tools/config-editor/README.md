# CastleGuard 配置工具

在仓库根目录运行：

```bash
python3 tools/config-editor/server.py
```

浏览器打开 `http://127.0.0.1:8780`。顶部可切换关卡、技能树和基础数值，左侧选择编辑对象，中间查看总览，右侧修改详细属性。顶部“保存配置”直接写入当前分类对应的源文件：

- `code/axmol/CastleGuard/Content/config/waves.json`
- `code/axmol/CastleGuard/Content/config/upgrades.json`
- `code/axmol/CastleGuard/Content/config/monsters.json`

“基础数值”页先按现有配表分为“怪物”和“成长初始值”。怪物分类可编辑全局基础移速、基础体型半径，以及每种怪物的生命、移速倍率、体型倍率、行动强度与间隔、驻足范围、击退倍率和金币掉落；保存到 `monsters.json`。类型对照表中的移速由全局基础移速乘以类型倍率计算。未保存的移速修改也会立即反映到关卡配置页的参考值和预览器；保存接口按游戏 `MonsterBalance` 的范围规则检查输入。

怪物对照表展示所有类型的外形缩略图；选中怪物的大图在桌面显示于右侧，在窄屏显示于表格上方。预览按当前游戏 `MainScene::applyMonsterSkin` 的静态形状绘制；基础体型半径和类型体型倍率修改后立即重绘。若游戏中的程序化造型发生变化，需要同步更新工具的 `monster-visual.js`，避免预览与实战不一致。

“成长初始值”分类读取 `upgrades.json` 中每个成长属性 `values[0]`，按军械所、研究院和城防营展示，可编辑并保存到同一个 `upgrades.json`；首次升级及后续等级仍由技能树页管理。两个入口共用同一份未保存草稿。当前未进入配表的战斗常量不在此页展示，避免编辑器出现无法保存或不会影响游戏的虚假设置。保存后重启游戏应用新值。

关卡页右上角的“预览关卡”会按当前未保存的配置展示整关波次。可播放/暂停、拖动时间轴、切换波次和调节播放速度；横排同帧、长列逐个和各组延迟按配表展开。战场画布按游戏 720×1280 的竖屏设计比例显示，城墙、出生点与 12 条车道按战斗视角的相对位置布置。默认使用固定示意位置和速度；怪物的击杀时间和下一波开始时机取决于实战，预览不模拟战斗结算。

“模拟随机”开启后，每次重新播放会重抽未指定的车道、散列怪的横向偏移、侧翼入场高度，以及默认移速的个体随机系数（0.85–1.15 倍）。拖动时间轴保持同一次抽样；指定移速与横排/长列的对齐规则不变。预览按 720×1280 的设计画布与怪物类型速度估算直线行进时间，不模拟战斗中的停步、游荡、击杀等行为；实际屏幕更高时，行进时间也会不同。

关卡组的“使用指定移速”对应 `useConfiguredSpeed`。开启后填写 `configuredSpeed`（像素/秒）；整组怪物使用这个绝对速度，关闭时沿用怪物类型倍率和个体随机速度。当前第 7 关的混合横排是示例。

出怪组旁显示各怪物类型的默认基准移速，数值与游戏运行时共同读取 `code/axmol/CastleGuard/Content/config/monsters.json`。单一类型首次开启指定移速时填入该类型基准；混合类型没有统一基准，需要手动输入整组速度。已配置的指定速度不会因切换怪物类型而自动覆盖。

技能树工具编辑既有 ID 的布局、前置关系和数值。新升级/法术 ID 仍需要先在游戏的 C++ 枚举与效果逻辑中接入；编辑器不会凭空创建可运行的新技能。页面提供快速输入检查，保存后仍应运行游戏测试，最终以游戏自己的配置解析结果为准。

服务只监听本机 `127.0.0.1`。保存采用文件版本比对和原子替换：如果配置被别处修改，页面会要求重新载入，避免覆盖新内容。未保存状态按三个源文件分别记录；保存按钮保存当前分类对应的源文件。

服务测试：

```bash
python3 -m unittest discover -s tools/config-editor -p 'test_*.py'
node --test tools/config-editor/test_preview.cjs
```

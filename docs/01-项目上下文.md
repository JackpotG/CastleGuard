# 01 项目上下文

> 本文档沉淀项目缘起与前期讨论结论，是后续所有开发决策的基准。修改设计方向时先改这里。

## 一、原作分析：《Defender II》（守卫者2）

DroidHen 工作室出品的城堡防守类塔防手游（约 2013 年）。核心玩法：玩家触摸屏幕控制射箭方向击杀进攻的怪物波次，拖放图标释放法术（消耗魔法值），局外用金币升级弓箭威力/数量/射速与城墙，用水晶升级魔法和魔法塔，并带有"比谁守得久"的联网对战模式。

### 值得保留的核心（复刻对象）

1. **操作极简**：单指点射/长按连射 + 拖放技能，3 秒上手，天然适配手机与微信小游戏。
2. **双资源养成线**：金币升弓箭/城墙，水晶升魔法/魔法塔，目标感清晰。
3. **异步对战模式**：比谁守得久——搬到微信生态（好友排行、分享挑战）几乎是量身定做。

### 必须优化掉的问题

1. **后期重复度极高**：200+ 关本质是同图加数值，几十关后即疲劳。
2. **数值曲线粗暴**：后期靠高伤怪硬堆逼氪，挫败感而非策略感。
3. **画面特效过时**：2013 年美术水准。
4. **无社交裂变设计**：纯单机 + 弱联网，无传播钩子。

## 二、复刻优化方向（针对微信小游戏生态）

1. **可持续内容体系**：首发目标 4 章 20 关，以怪物职责、威胁预算、精英词缀、战场规则和可选挑战组合内容，不依赖无限堆血量与数量；完整方案见 `docs/08-长期耐玩与灰度实验设计.md`。
2. **双轨三选一**：额外的“无尽守城”模式每 3 波发放仅本局生效的 Roguelike 增益；普通推关则在首次通关后发放一次永久养成三选一。两者共用展示面板，但状态、生命周期和存档完全分离。
3. **产品化入口**：从 Demo 式模式弹窗升级为主城首页，统一承载主线、无尽、每日挑战、工坊、图鉴、排行和设置。
4. **构筑与装备成长**：重构 Buff/属性结算，增加全局弓术研究、横向武器换装、城墙本体与被动设施；玩家可接管弓手台、魔法塔、投石机等武器站，其余武器按可配置规则自动攻击，详见 `docs/09-战斗成长与装备系统设计.md`。
5. **可信实验与灰度**：使用稳定玩家分组、互斥实验层、配置快照、曝光事件和安全回退验证难度、奖励与入口方案；修复、合规和存档协议不做 A/B。
6. **社交化改造对战**：好友排行榜（开放数据域）、分享战绩卡片（"我守到了第 87 波"）、每日巅峰赛。
7. **变现**：纯广告变现起步（激励视频复活/双倍结算/免费水晶）。内购需版号，周期长；纯广告只需备案，上线快。
8. **数值重做**：用怪物机制组合（护盾怪+快速怪+治疗怪）替代硬堆伤害，逼玩家换技能策略；前 20 关曲线平滑，每章按“引入→检验→组合→变体→Boss”组织。

M1 首轮落地为 5 关短战役：第 3/4/5 关依次自动解锁火球、冰冻、箭雨；关卡出怪量、奖励与升级节奏见 `docs/06-五关数值验证.md`。2026-11-18 已完成无说明真人盲测，暂未发现阻塞问题，M1 闭环通过并进入 M2。

## 二·五、视角决策（2026-11-16 与 Stark 定稿）

- **双视角版本并行**：
  - **Oblique25D 伪 2.5D 斜俯视 = 原作构图（主线）**：城墙在底部窄边、出怪线在顶部窄边，怪物沿多车道（纵排）上→下推进；车道即轨迹，地面用上浅下深的色带表现远近。
  - **SideView 纯侧视角 = 新增风格版本**：底部一条地面、左侧灰色房子为防守目标，怪物从右缘进入沿地面右→左进攻（单条地面轨迹）。
  - 两版是**同一套"多车道"规则的两种呈现**（原作就是多车道出怪，车道同时编码远近）；玩法逻辑应基于"车道编号 + 沿车道进度"的统一数据模型，呈现层各画各的。
- **横竖屏适配原则**：不做两份手工场景。所有布局按**当前可见尺寸**计算，尺寸变化（旋转/窗口缩放）走同一条 `buildBattlefield` 重建路径；微信端放开方向后由 `wx.onWindowResize` 触发同一机制。
- **调试入口**：桌面按 `1`/`2` 键切换视角；模拟器/真机用左上角常驻调试按钮（矩形热区 + containsPoint 判定）或双指点按。滑杆按钮/桌面 `T` 打开 ImGui 开发者工具，其中“沙盒”页可改持久化资源与成长、强制胜负和开启当前局作弊；全部受 `CG_DEBUG_TOOLS` 保护，正式包整块剔除。

## 三、远期产品目标：多端互通

> 这是产品远期方向，不是当前 MVP 范围；任何阶段都不得为了它破坏“串行推进、先 MVP、发布验收”的铁律。

### 目标边界

1. **跨端账号**：同一游戏账号可绑定微信小游戏、移动端 App 等多个渠道身份，支持跨端云存档。
2. **跨端异步社交**：不同渠道玩家可以添加游戏内好友、查看全球/好友排行榜、分享并挑战彼此战绩。
3. **实时联机暂缓**：同局合作或实时对战属于更后期实验方向，只有跨端账号与异步社交稳定后再单独评估。

### 架构原则

1. **渠道身份 ≠ 游戏账号**：微信 OpenID/UnionID、App 登录身份、游客身份都只是登录凭证；服务端使用独立的 `account_id` 作为主身份。
2. **玩法代码不直接依赖平台 API**：账号、存档、好友、排行等能力通过抽象接口隔离；当前阶段可先使用本地实现，未来替换为服务器实现。
3. **微信好友系统与跨端好友系统并存**：微信开放数据域继续负责微信生态内排行与分享；跨端好友关系由自有服务器维护。
4. **数据与协议引擎无关**：存档格式、数值配置、战绩结构优先采用 JSON 等引擎无关格式，为 Unity 版本复用做准备。

### 阶段安排

- **第一站 Cocos 阶段**：不做多端服务端；只在代码结构上避免把账号、存档、排行写死在微信 API 上。
- **第二站 Unity App 后期**：评估并实现“多端互通 V1”——统一账号、云存档、跨端好友码、全球排行榜、异步战绩挑战。
- **第三站之后**：再评估实时联机合作/对战。

## 四、MVP 范围（任何引擎版本的第一刀）

- 一张城堡防守地图
- 怪物从右向左的波次进攻（5 种怪以内）
- 点击或长按射箭 + 3 个技能（原作技能体系：火/冰/电三系魔法塔、每系 3 阶递进——火球→流星→末日审判 /
  冰锥→冰霜新星→冰河世纪 / 闪电→闪电风暴→诸神的黄昏；交互为拖放法术图标释放。
  我们 M1 简化为 火球 / 冰冻减速 / 箭雨 三个固定技能，考据详见 docs/05）
- 过关结算金币/水晶
- 局外升级界面

> 预期 2~3 周做出，先验证手感再谈系统。

## 五、合规红线

- **不碰原作素材**："守卫者2 / Defender II"名称、美术、音乐均为 DroidHen 版权。玩法机制可借鉴，素材全部重做或购买授权素材。
- **微信平台要求**：实名认证 + 防沉迷接入；主包 4MB 限制，美术走分包 + CDN。
- **版号**：含内购必须申请版号；纯广告变现走备案即可（立项期策略）。

## 六、技术要点备忘（微信小游戏 / Axmol · Cocos2d-x C++ 裸引擎）

> 技术路线（2026-11-13 定稿）：不用 Cocos Creator 图形化开发；经调查确认微信官方"通用引擎适配方案"已支持 Cocos2d-x（C++ → Emscripten → WASM+WebGL → 转换为小游戏），故第一站改用 **Axmol**（cocos2d-x 4.0 社区维护分支，原生支持 WASM 构建）纯 C++ 开发，目标是深入渲染管线与引擎原理。同日较早记录的"Creator 纯代码流"约定被本决策取代。降级预案：若 WASM→小游戏链路被工具/合规卡住，以 H5 + Android APK 发布验收。
>
> 官方方案核实（2026-10-13 版文档）：转换工具（v1.0.35）与能力 SDK（v1.0.3）已开放下载；能力 SDK 提供网络/文件系统/音频/触摸适配及微信登录、分享、支付、广告接口；推荐 Emscripten 3.1.51（需锁定 axmol 的 emsdk 版本）。
>
> **2026-11-13 实测修正**：微信推荐的 emsdk 3.1.51（及 3.1.53）无法编译 axmol——emscripten 到 3.1.73 才自带 `AL/alext.h`，而 axmol 音频层必须包含它。实际锁定 **3.1.73**（axmol 官方默认值）。能力 SDK 目前只提供 emsdk3.1.10/3.1.51 预编译变体，集成时可能有 ABI 兼容风险，需届时实测。详见 `docs/04-环境搭建与工具链.md` 排雷 5。

- 同屏怪物+箭矢可能上百：必须对象池，简单圆形碰撞 + 空间分格，不用物理引擎。
- 弓箭、怪物用 Spine 骨骼动画，比序列帧省体积（Axmol 以扩展形式支持 Spine）。
- 性能预算概念（draw call、合批、图集）是这一站的渲染入门课；裸引擎源码全开放，可直接读渲染器实现。
- WASM 目标约束：主包 JS ≤ 2MB、建议禁用内存动态增长（预设 INITIAL_MEMORY）、无 SharedArrayBuffer 多线程——架构上避免依赖多线程。

# 09 战斗成长、武器与城防系统设计

> 状态：设计草案 V1（2026-11-18）。本文件承接 `docs/08-长期耐玩与灰度实验设计.md`，定义 Buff 重构、武器成长与替换、城墙成长和被动防御火力。

> 2026-11-18 共享战斗核心追加：城墙/Boss 生命 HUD 与箭矢击退 V1 已落地，玩法核心、闯关和肉鸽共用；下一步按本文第三章升级 Buff 与属性系统。

## 一、参考原版，但不复制原版

《Defender II》的官方商店说明明确列出：力量提高箭矢伤害、敏捷提高射击频率、玩家可以选择并装备弓；城墙升级提高生命，击退和概率双倍伤害是弓箭侧能力，魔法塔同时提供法力与被动攻击，另有熔岩护城河。来源：[Defender II - Google Play](https://play.google.com/store/apps/details?id=com.droidhen.defender2)。

CastleGuard 借鉴的是这套**职责分层**，不是原版名称、素材或数值：

- 玩家武器是持续主动输出核心。
- 局外研究提供跨武器的基础成长。
- 装备不同武器改变手感和打法，而不是单纯换成更大的数字。
- 城墙既有生存成长，也能装备被动防御模块。
- 魔法塔同时服务法力循环和低频被动攻击。
- 局内 Buff 只塑造本局流派，不覆盖局外装备价值。

原版后期容易出现“只有一把最强武器值得使用”的问题。本项目的武器采用横向取舍，所有武器都有适用场景，不做线性淘汰。

## 二、成长系统分层

所有加成都进入同一条属性结算管线，但不能把所有东西都叫 Buff：

| 层级 | 示例 | 生命周期 | 是否存档 |
|---|---|---|---|
| 基础模板 | 初始箭伤、基础射速、城墙生命 | 版本配置 | 否 |
| 永久研究 | 力量、敏捷、多重箭、城墙加固 | 永久 | 是 |
| 已装备内容 | 当前武器、城防模块、魔法塔 | 换装前持续 | 是 |
| 局内增益 | 无尽三选一 | 单局 | 否 |
| 限时状态 | 暴击标记、减速、眩晕、中毒 | 数秒 | 否 |
| 关卡规则 | 逆风、魔力涌动、精英增援 | 单关 | 否 |

固定结算顺序：

```text
基础模板
  -> 永久研究
  -> 武器/城防/魔法塔装备
  -> 关卡规则
  -> 局内增益
  -> 限时状态
  -> 上下限校验
  -> 本局战斗快照
```

购买、换装或远程配置变化都不能直接修改正在战斗的对象。开局生成不可变快照，下一局才使用新配置。

## 三、Buff 与属性系统重构

### 3.0 已落地的前置能力

- 城墙生命在开局时固化本局最大值，战斗 HUD 常驻显示当前值/最大值；Boss 出场时显示生命条，多 Boss 同场按总生命汇总。
- `PlayerCombatStats` 已包含箭矢击退距离；每支箭在发射时固化该值，飞行途中升级或 Buff 变化不会追改。
- `MonsterParameters` 已包含击退承受系数，Boss 默认 `0.20`；开发者工具修改只影响之后出生的怪物。
- 命中后按“怪物当前位置 - 城墙目标点”取得远离城墙方向，位移分帧结算；贴墙或驻足单位被推出攻击范围后回到行走状态。
- 护盾免疫箭矢、护符成功挡伤以及已死亡目标不触发击退。当前击退仅属于箭矢物理命中，技能是否击退由后续统一 `DamagePacket` 明确声明。

这一步先把击退做成可迁移的战斗属性，而不是散落在动画代码中的固定像素。V2 接入后，击退由 `DamagePacket` 携带，运行时位移层继续复用。

### 3.1 当前问题

当前 `RunBuffModel` 只有四个层数计数器，冰冻、麻痹等怪物状态则直接存为独立计时器。它足够支撑 Demo，但继续增加武器特性、精英词缀、被动设施和元素效果后会出现：

- 同一属性在多个位置重复计算。
- 加成顺序不明确，数值容易因先乘后加产生漂移。
- 状态叠层、刷新、互斥和来源无法统一表达。
- UI、开发工具和战斗逻辑可能各保存一份规则。

### 3.2 V2 结构

引入三个纯逻辑概念：

1. `AttributeSet`：角色、武器、城墙或怪物的基础属性集合。
2. `Modifier`：对一个属性进行固定值、百分比或乘区修改。
3. `EffectInstance`：某个效果当前的来源、层数、剩余时间和触发状态。

效果定义包含：

- 稳定 `effectId` 和标签。
- 目标域：玩家、武器、城墙、怪物或战场。
- 生命周期：永久来源、整局、限时、光环、一次性触发。
- 叠层规则：叠加、刷新时间、取最高、唯一、互斥组。
- 最大层数和数值修饰器。
- 可选触发器：射击、命中、击杀、城墙受击、波次开始或结束。

V1 只实现白名单内的类型化触发器，不在 JSON 中加入任意脚本。配置负责数据，C++ 负责经过测试的行为。

### 3.3 属性公式

普通数值统一使用：

```text
final = clamp((base + flatSum) * (1 + percentSum) * multiplierProduct)
```

射速内部改用“每秒射击次数”，最后再换算成射击间隔，避免“间隔减少”和“射速提高”混算。概率统一限制在合法范围；多重箭、穿透次数等整数属性最后取整。

首批属性：

- 武器：伤害、每秒射击次数、弹体数、散射角、暴击率、暴击倍率、击退、穿透、元素附伤。
- 城墙：最大生命、护甲、每波修复、屏障、近战反伤。
- 怪物：移动速度、行为频率、造成伤害、承受伤害、状态抗性。

### 3.4 状态迁移

- 无尽四种增益迁入 `EffectContainer`，候选与选择规则仍由 Roguelike 奖励池拥有。
- 冰冻和麻痹从裸计时器迁为限时效果。
- 未来的中毒、灼烧、破甲和精英光环使用同一容器。
- 永久升级和装备不是 `EffectInstance`；它们只在生成战斗快照时贡献修饰器。

## 四、武器研究、升级与替换

武器成长分成两层，解决“换武器后旧投入全部浪费”的问题。

### 4.1 全局弓术研究

所有武器共享：

- 力量训练：基础箭伤。
- 敏捷训练：射击频率。
- 齐射训练：多重箭数量与散射控制。
- 致命训练：暴击概率和暴击倍率，参考原版 Fatal Blow 的职责。
- 冲击训练：击退与破甲，参考原版 Power Shot 的职责。

现有强弓、疾射、多重箭等级迁移到前三条研究，玩家投入不丢失。

### 4.2 武器装备与专属升级

玩家只装备一把主武器，战斗外可免费切换。每把武器有自己的等级和标志性特性：

| 武器定位 | 主要优势 | 主要代价 | 标志性玩法 |
|---|---|---|---|
| 城防长弓 | 均衡、容易瞄准 | 无极端优势 | 新手与通用配置 |
| 连发弩 | 高频率、压制小怪 | 单发伤害低 | 暴击与元素触发 |
| 破阵重弩 | 高伤、穿透、击退 | 射速慢 | 对付护盾、精英和直线编队 |
| 风行短弓 | 多重箭、转向灵活 | 散射较大 | 清理快速怪与两翼夹击 |
| 元素战弓 | 技能联动、附加状态 | 纯物理输出较低 | 火/冰/电构筑 |

名称与外观均为项目原创占位，后续可随世界观调整。

武器数据拆为：

```text
WeaponDefinition：weaponId、基础属性、成长曲线、解锁条件、特性、表现资源
WeaponProgress：是否拥有、武器等级
Loadout：当前 equippedWeaponId
```

武器等级首版设 1~10 级，使用金币升级；章节 Boss 掉落“蓝图解锁资格”，水晶用于正式解锁。蓝图只是条件，不新增第三种常驻货币。

武器必须保持横向选择：升级提高其优势，但不能把慢速重弩升级成没有缺点的高速武器。新武器不能简单覆盖旧武器的全部属性。

## 五、城墙本体与被动设施

城防拆为“城墙本体 + 被动设施 + 可驾驭武器站”。三者必须分开：城墙负责生存，被动设施无需瞄准，武器站既可由玩家接管，也可按规则自动攻击。

### 5.1 城墙本体成长

- 城墙加固：提高最大生命。
- 护甲工事：降低每次受到的直接伤害，有明确减伤上限。
- 修缮队：每波结束修复一定生命，不能超过上限。
- 应急屏障：每局一次，在生命过低时吸收固定伤害。

现有城墙等级迁移为“城墙加固”等级。

### 5.2 永久自动的被动设施

被动设施不接受玩家瞄准，也不占武器站槽位。首版装备一个设施：

| 设施 | 伤害类型 | 行为 | 战术职责 |
|---|---|---|---|
| 荆棘拒马 | 物理 | 近战怪攻击城墙时受到反伤 | 惩罚贴墙群怪，不处理远程怪 |
| 烈焰壕沟 | 火焰 | 城墙前周期性产生灼烧区域 | 清理密集低血怪，参考原版熔岩护城河的职责 |
| 寒霜信标 | 冰霜 | 周期脉冲造成低伤并减速 | 延长玩家输出窗口，伤害不是主卖点 |

V1 先实现荆棘拒马和烈焰壕沟，验证反伤与持续区域伤害；寒霜信标后续复用效果系统。

### 5.3 伤害类型规则

首批伤害类型为物理、火焰、冰霜、雷电和奥术。类型首先表达**行为差异**，不立即加入复杂隐藏抗性：

- 物理：直接伤害、击退、穿透或反伤。
- 火焰：区域伤害与持续灼烧。
- 冰霜：低伤害与减速控制。
- 雷电：连锁和短暂麻痹。
- 奥术：稳定伤害并与法力循环联动。

等图鉴和战斗提示能清楚展示弱点后，再评估怪物抗性。没有可读反馈前不做“看不见的减伤”。

所有伤害统一通过 `DamagePacket` 进入怪物扣血入口，至少包含来源、伤害类型、基础值、标签和命中编号。反伤包带有不可再次反射标签，防止触发循环。

## 六、武器站驾驭与自动作战

### 6.1 核心规则

城墙最多部署三个武器站：初始弓手台固定存在，另外两个槽位可装备魔法塔、投石机、弩炮等。任意时刻玩家只接管一个武器站，其他已部署武器保持自己的装填与充能，并按预设规则自动攻击。

接管只改变输入和目标选择权，不改变武器属性，也不重置冷却、装填、弹药、热量或充能。这样可以随战况切换，但不能靠来回切换刷攻击。

### 6.2 武器站类型

| 武器站 | 玩家接管时 | 自动模式 | 战术职责 |
|---|---|---|---|
| 弓手台 | 按住连续瞄准射击，可快速转火 | 攻击最接近城墙的目标 | 持续输出与补刀 |
| 魔法塔 | 点击锁定特殊敌人，消耗塔自身充能释放元素重击 | 按策略攻击治疗、召唤、护符等高价值目标 | 特殊敌人点杀与技能循环 |
| 投石机 | 拖动范围圈，抬起向区域抛射 | 选择怪物密度最高的区域 | 大范围杀伤，装填慢 |
| 守城弩炮 | 选择一条射线蓄力贯穿 | 优先精英、Boss 或直线编队 | 高穿透单体与列队压制 |
| 风暴尖塔 | 指定连锁起点，手动决定传播方向 | 优先快速怪和残血怪 | 分散目标处理与控制 |

V1 先完成弓手台、魔法塔和投石机，覆盖持续瞄准、目标锁定和范围落点三种手动操作。弩炮与风暴尖塔在输入框架验证后追加。

### 6.3 自动攻击规则

自动模式不是不可解释的“智能 AI”。玩家在工坊为每个武器选择一个目标策略：

- 最近城墙。
- 生命最低。
- 精英/Boss 优先。
- 支援怪优先。
- 飞行怪优先。
- 怪物最密集区域，仅供投石机等范围武器使用。

每种武器只开放适合自己的策略。自动目标由确定性评分函数选择，同样输入必须得到同样结果；没有合法目标时保持待机，不向空地浪费关键弹药。

自动武器只使用基础攻击，不代替玩家释放标志性重击。它有短暂目标获取延迟，整体效率目标为玩家熟练接管时的 75%~85%，既有价值又保留操作收益。

### 6.4 战斗内切换与输入

- 技能栏上方显示固定尺寸的武器站切换条，图标展示类型、装填进度和当前控制状态。
- 点图标接管武器；原武器立即切回自动模式，当前装填不丢失。
- 弓手台使用长按与拖动；魔法塔使用点击锁定；投石机使用拖动范围、抬起发射。
- 模态面板、技能拖放和开发工具仍优先，切换按钮不能穿透成一次攻击。
- 武器站被关卡禁用或摧毁时自动回到弓手台，不保留悬空输入状态。

主动技能继续使用共享法力。魔法塔的手动元素重击使用塔自身充能，自动基础攻击不消耗玩家法力，避免自动系统擅自花掉玩家资源。

### 6.5 运行时结构

- `WallWeaponDefinition`：稳定 ID、基础属性、手动操作类型、自动策略白名单、表现资源。
- `WallWeaponProgress`：拥有状态、等级和解锁信息。
- `WallWeaponRuntime`：本局装填、充能、热量、当前目标和自动/接管状态。
- `WallWeaponSystem`：统一更新所有武器站并管理当前 `controlFocus`。
- `AutoTargetPolicy`：调用生产目标评分，不在 UI 或调试面板复制算法。

武器站只向统一弹体、效果和 `DamagePacket` 接口提交攻击，不直接操作怪物生命。输入适配器只产生瞄准点、目标 ID 或区域，不拥有伤害规则。

### 6.6 火力预算

一套成熟配置的初始伤害占比目标：

- 玩家当前接管的武器站：约 45%。
- 其余自动武器站：合计约 25%。
- 主动技能：约 20%。
- 拒马、壕沟等纯被动设施：约 10%。

这是调参目标，不是硬编码。结算必须分别统计手动与自动武器伤害、目标浪费率、控制时间和设施伤害，防止玩家停止操作后仍能稳定通过同等级关卡。

## 七、魔法塔与技能成长

魔法塔既是可驾驭武器站，也提供少量法力恢复。自动模式只进行低频基础攻击；玩家接管后可积攒并释放元素重击，用于优先点杀治疗、召唤或护符怪。

完整魔法塔 V2 再增加：

- 法力上限和恢复速度。
- 火、冰、雷三系塔等级。
- 每系主动技能等阶与接管重击特性。
- 战前选择技能组合，而不是把所有技能同时塞进底栏。

魔法塔、被动设施和主动技能共用效果与伤害入口，但升级数据和装备槽独立。这样可以参考原版结构，又不把当前四个技能推倒重做。

## 八、工坊、编组与战斗页面

主菜单的“城堡工坊”拆为五个标签：

1. **武器库**：弓类武器的拥有状态、等级、属性对比和装备按钮。
2. **弓术研究**：全局伤害、射速、多重箭、暴击、冲击。
3. **城墙工事**：城墙本体和一个被动设施槽。
4. **武器站编组**：两个扩展槽、默认接管武器、每个武器的自动目标策略。
5. **魔法塔**：法力与法术成长；未完成前显示明确的未开放状态。

属性比较必须显示“当前值 -> 装备后值”，并单独列出标志性特性。换装和调整自动策略免费且可逆；升级是消耗资源的永久选择，需要二次确认和购买结果反馈。

结算页不再承载完整升级商店，只提供“继续”“回主城”“前往工坊”三个明确去向。

## 九、经济与解锁节奏

首版继续使用两种资源：

- 金币：全局研究、武器等级、城墙本体、设施和武器站等级。
- 水晶：新弓、设施、武器站和魔法塔阶段解锁。

建议章节节奏：

- 第一章：长弓、三条基础研究、城墙加固、荆棘拒马。
- 第二章：连发弩、冲击训练、烈焰壕沟、修缮队、投石机。
- 第三章：重弩、致命训练、魔法塔、应急屏障。
- 第四章：风行/元素弓、弩炮/风暴尖塔和高阶编组。

首通三选一可以提供研究等级、指定设施/武器站经验或资源，但不能直接随机替换玩家当前编组。核心装备解锁必须有明确里程碑，不使用抽卡。

## 十、存档与迁移

存档新增稳定 ID，而不是数组下标：

- `researchLevels[researchId]`
- `weapons[weaponId] = { owned, level }`
- `equippedWeaponId`
- `wallCoreLevels[upgradeId]`
- `defenseFacilities[facilityId] = { owned, level }`
- `equippedFacilityId`
- `wallWeapons[wallWeaponId] = { owned, level }`
- `equippedWallWeaponIds[]`、`defaultControlWeaponId`
- `autoPolicyByWallWeaponId[wallWeaponId]`

旧存档迁移：

- 强弓 -> 力量训练。
- 疾射 -> 敏捷训练。
- 多重箭 -> 齐射训练。
- 坚固城墙 -> 城墙加固。
- 默认赠送城防长弓与弓手台，并将弓手台设为默认接管武器。

迁移必须幂等，并用旧版本存档样本自动测试，不能让已有玩家重新购买同一成长。

## 十一、A/B 与数据验证

安全实验项：无尽 Buff 权重、自动瞄准效率、武器解锁展示、关卡内临时系数。永久价格、已购买物品结果和存档迁移首版不做 A/B，避免不同组玩家形成不可逆资产差异。

新增事件：

- `weapon_unlock`、`weapon_upgrade`、`weapon_equip`。
- `wall_weapon_unlock`、`wall_weapon_equip`、`control_switch`、`auto_policy_change`。
- `research_upgrade`、`wall_upgrade`、`facility_equip`。
- `buff_offer`、`buff_select`、`effect_applied`。
- `battle_build_snapshot`、`damage_summary`。

关键分析：各武器接管时长、切换次数、手动/自动伤害比、自动空射率、武器使用率、换装后胜率、城墙受击与修复量、设施空置率、Buff 选择率。任何单一武器长期占用率过高，都说明横向选择失败。

## 十二、实施顺序

1. 建立属性、修饰器、效果容器和统一伤害包，迁移现有无尽 Buff、冰冻、麻痹与击退。
2. 建立 `BattleLoadoutSnapshot`，保证永久成长、装备和局内增益只在一个地方结算。
3. 完成全局弓术研究与旧存档迁移。
4. 完成长弓、连发弩、重弩三把弓类武器和换装页面。
5. 建立武器站运行时、控制焦点、自动目标策略和切换 UI。
6. 完成弓手台、魔法塔、投石机，以及荆棘拒马和烈焰壕沟。
7. 接入手动/自动伤害来源统计、开发者工具和自动测试。
8. 再扩充弩炮、风暴尖塔、魔法塔等阶和 20 关内容。

首批验收：

- 旧存档升级后属性不降低，已购等级不丢失。
- 三把弓类武器的操作手感和适用目标明显不同，没有全属性更优者。
- 玩家可在三个武器站之间切换，其他武器自动攻击且切换不重置装填。
- 魔法塔能手动点杀特殊敌人，投石机的范围落点与伤害反馈清晰。
- 自动策略行为可预测，无目标时不会浪费关键攻击。
- 局内 Buff 清空不影响永久研究、装备和武器站编组。
- 停止操作后不能稳定通过同等级关卡。
- 所有伤害来源可追踪，反伤与连锁不会递归触发。
- 桌面、WASM、正式构建和存档迁移测试通过。

## 十三、明确暂不做

- 不复制原版武器名称、外观、图标或具体数值。
- 不增加随机抽武器或武器耐久度。
- 不让新武器按稀有度线性淘汰旧武器。
- 不在第一版加入复杂元素抗性和克制表。
- 不让配置文件执行任意脚本。
- 不让自动武器和被动设施取代玩家操作。
- 不用切换控制权重置装填、充能或冷却。

# 技能树配表与运行时节点

更新：2026-11-25。

## 编辑流程

1. 打开 `tools/config-editor/` 的技能树页，选择军械所、研究院或城防营。
2. “新建节点”添加基础节点；选中现有节点后的“子节点”自动填写前置关系。下一层没有空位时，会寻找后续可用层。
3. 填写稳定 ID、名称、说明、货币、可进入的解锁关卡及位置。在“前置条件 · 全部满足”中增减前置项，每项单独选择节点与要求等级；位置预设支持多前置居中。
4. 增减升级等级，设置各级购买价格；增减效果卡，选择属性、计算方式及各级数值。
5. 保存配置；重新构建游戏资源后启动游戏，新节点会出现在所属设施中。当前没有运行时热重载。

节点 ID 用于存档，名称可以随时修改。修改 ID 会成为另一条独立成长记录；工具会同时更新草稿中的前置引用。删除节点会移除它的效果与入口，但不会清除旧存档里的对应键，重新使用相同 ID 会读回旧等级。不要把已有 ID 分配给含义不同的新节点。

删除有子节点的节点时，须先移除或修改子节点的前置引用。修改最大等级后，已有存档等级会被限制在新的最大等级内。

## 节点与效果分离

`upgrades.json` 的 `upgrades` 数组不再要求固定 9 个节点。游戏按目录生成临时句柄，UI 按目录创建节点，存档使用 `cg.save.upgrade.<id>`。原有 9 个升级仍可读取旧式 `values` 配置；工具打开后将其转换为显式 `effects`，保存时写出新格式。

一个新节点的示例：

```json
{
  "id": "focused_shot",
  "name": "凝神射击",
  "description": "增加伤害并缩短射击间隔",
  "track": "bow",
  "treeRow": 2,
  "treeX": 0.5,
  "prerequisites": [
    {"id": "precision", "level": 1},
    {"id": "heavy_strike", "level": 1}
  ],
  "unlockStage": 3,
  "currency": "coins",
  "costs": [10, 25],
  "effects": [
    {"attribute": "arrow_damage", "operation": "add", "values": [0, 2, 4]},
    {"attribute": "fire_rate", "operation": "multiply", "values": [1, 0.9, 0.8]}
  ]
}
```

`costs[0]` 是升到 1 级的价格，`effects[*].values[0]` 是未升级时的效果。每个效果的数值数量必须等于价格数量加 1。最多配置 50 级；军械、研究院布局层级为 0–16，同层节点至少相隔 0.18，横向范围为 0.12–0.88。

`prerequisites` 中的所有条件为 **且（AND）** 关系：上例要求“鹰眼 1 级”与“强力一击 1 级”同时满足，任意一项未满足都不能购买，也不会扣款。空数组表示无前置；同一节点不可重复引用。工具与游戏为每项绘制一条折线，游戏中按该项是否满足分别着色，并列出未满足的等级要求。

游戏兼容原有单项 `requires` / `requiredLevel` 字段；工具打开后迁移为 `prerequisites`，保存时不再写出旧字段。新旧前置格式不可混用；节点改名 ID 会同步更新所有引用。法术研习也支持多个前置法术，每项 `level` 固定为 1，表示该法术已解锁。默认解锁的法术不能配置前置；自动解锁的关卡不能早于任何前置法术。

`unlockStage` 为 0 时不限制关卡，否则玩家可进入该关时允许购买。解锁条件本身不赠送等级，也不扣除额外费用，第一次升级按 `costs[0]` 购买。前置节点必须属于同一设施且在更早的层，避免循环。城防节点沿用横向等级分支展示。

## 支持的战斗属性

属性目录位于 `Content/config/upgrade-attributes.json`，游戏与编辑器共用其标识、名称、基础值和范围；游戏中另有配置失效时使用的保底目录与安全上限。编辑器通过只读接口加载属性目录。

| 属性 ID | 含义 |
| --- | --- |
| `arrow_damage` | 箭矢基础伤害 |
| `fire_rate` | 基础射击间隔的倍率，越小越快 |
| `multi_shot` | 每次齐射箭数 |
| `wall_health` | 城墙生命上限 |
| `heavy_strike` | 箭矢击退距离 |
| `precision` | 暴击概率，0.12 表示 12% |
| `mana_flow` | 每秒额外法力恢复 |
| `wall_armor` | 城墙护甲 |
| `spell_efficiency` | 法术耗蓝倍率，越小越省蓝 |

效果支持三种计算方式：

- `set`：设置该属性的基础成长曲线。一个属性最多一个 `set` 效果；删除后回到属性目录的基础值。
- `add`：增加数值。未升级值必须为 0，避免未购买就获得加成。负值可用于代价或权衡。
- `multiply`：乘以倍率。未升级值必须为 1，各级倍率须大于 0。

最终属性为 **（基础值 + 所有 add 加值）× 所有 multiply 倍率**，最后限制在属性的安全范围内；生命、伤害、箭数等整数接口沿用取整。该计算顺序不受节点在文件中的排列顺序影响。游戏内图标根据节点的首个效果属性绘制，复合效果按行展示。

可以用这些属性组合任意数量的成长节点。新增穿透、召唤、连锁攻击等全新机制，仍需先实现相应战斗逻辑并注册属性；四种主动法术继续使用已有施放逻辑，法术研习页不创建新的施法类型。

## 验证与排查

`UpgradeCatalog.cpp` 是游戏节点解析与效果计算入口。错误配置不会部分写入运行时目录，会记录 `[Progression][Research]` 日志并保留保底目录。工具保存前做输入检查，文件接口继续使用版本比对与原子写入。

`UpgradeCatalogTest.cpp` 覆盖旧格式、任意 ID、多前置 AND 门槛、独立等级、关卡限制、不满足时不扣款、重复/缺失/越界前置、复合效果、空目录及无效配置；`Tests/fixtures/editor-upgrades.json` 是通过浏览器实际新增和保存的配置样例。`Tests/fixtures/editor-multi-prerequisites.json` 是通过浏览器保存的多前置配置，同时覆盖升级节点与主动法术的运行时解析。测试程序只运行规则测试，不进入游戏窗口。

# 技能树配表与运行时节点

更新：2026-11-25。

## 编辑流程

1. 打开 `tools/config-editor/` 的技能树页，选择军械所、研究院或城防营。
2. “新建节点”添加基础节点；选中现有节点后的“子节点”自动填写前置关系。下一层没有空位时，会寻找后续可用层。
3. 填写稳定 ID、名称、说明、货币、可进入的解锁关卡及位置。在“前置条件 · 全部满足”中增减前置项，每项单独选择节点与要求等级；位置预设支持多前置居中。
4. 增减升级等级，设置各级购买价格；增减效果卡，选择属性、计算方式及各级数值。
5. 保存配置；重新构建游戏资源后启动游戏，新节点会出现在所属设施中。当前没有运行时热重载。

节点 ID 用于存档，名称可以随时修改。修改 ID 会成为另一条独立成长记录；工具会同时更新草稿中的前置引用。删除节点会移除它的效果与入口，但不会清除旧存档里的对应键，重新使用相同 ID 会读回旧等级。不要把已有 ID 分配给含义不同的新节点。

删除有子节点的节点时，须先移除或修改子节点的前置引用。修改最大等级后，已有存档等级会被限制在新的最大等级内。

## 所有设施共用配置流程

军械所、研究院和城防营使用同一套节点增删、等级与效果编辑、前置条件、位置预设、布局检查及连线流程。`track` 只区分所属设施，不再为城防营保留横向等级链或跳过位置检查。游戏也统一为“一个配置节点对应一个可升级图标”，按 `treeRow`、`treeX` 放置；点击图标购买下一级。

法术研习共用布局、位置预设和连线规则，层级范围也一致；其购买或自动解锁条件仍按主动法术的含义检查。游戏只绘制配表中的真实节点和前置关系，不额外添加法术根节点或写死的魔法塔占位。要加入具有新建造行为的魔法塔，须先实现对应游戏机制，再通过城防配表接入。

旧城防节点若缺少布局信息（未写 `treeRow`、`treeX`，或仅有旧值 `treeRow: -1`），工具和游戏会在内存中补齐：无前置放在首层，有前置放在最深前置的下一层，同层按稳定 ID 顺序安排空位；已有显式位置保持原样。读取不会改写源文件，下次主动保存时才写出布局。节点 ID、价格、效果和存档等级保持不变；不完整的显式布局仍报错，避免静默覆盖手工位置。

## 节点与效果分离

`upgrades.json` 的 `upgrades` 数组不再要求固定 9 个节点。游戏按目录生成临时句柄，UI 按目录创建节点，存档使用 `cg.save.upgrade.<id>`。原有 9 个升级仍可读取旧式 `values` 配置；工具打开后将其转换为显式 `effects`，保存时写出新格式。

一个新节点的示例：

```json
{
  "id": "focused_shot",
  "name": "凝神射击",
  "description": "增加伤害并缩短射击间隔",
  "track": "bow",
  "treeRow": 2,
  "treeX": 0.5,
  "prerequisites": [
    {"id": "precision", "level": 1},
    {"id": "heavy_strike", "level": 1}
  ],
  "unlockStage": 3,
  "currency": "coins",
  "costs": [10, 25],
  "effects": [
    {"attribute": "arrow_damage", "operation": "add", "values": [0, 2, 4]},
    {"attribute": "fire_rate", "operation": "multiply", "values": [1, 0.9, 0.8]}
  ]
}
```

`costs[0]` 是升到 1 级的价格，`effects[*].values[0]` 是未升级时的效果。每个效果的数值数量必须等于价格数量加 1。最多配置 50 级；军械所、研究院、城防营及法术研习的布局层级均为 0–16，同层节点至少相隔 0.18，横向范围为 0.12–0.88。

上述宽度和间距支持同层最多 5 个节点；4 个节点也可使用“同层级平均分配”。工具生成的均分坐标保留 6 位小数，避免浮点计算把边界 0.88 扩大为越界值；手工输入和游戏读取仍按原范围校验。

`prerequisites` 中的所有条件为 **且（AND）** 关系：上例要求“鹰眼 1 级”与“强力一击 1 级”同时满足，任意一项未满足都不能购买，也不会扣款。空数组表示无前置；同一节点不可重复引用。工具与游戏为每项绘制一条折线，游戏中按该项是否满足分别着色，并列出未满足的等级要求。

游戏兼容原有单项 `requires` / `requiredLevel` 字段；工具打开后迁移为 `prerequisites`，保存时不再写出旧字段。新旧前置格式不可混用；节点改名 ID 会同步更新所有引用。法术研习也支持多个前置法术，每项 `level` 固定为 1，表示该法术已解锁。默认解锁的法术不能配置前置；自动解锁的关卡不能早于任何前置法术。

`unlockStage` 为 0 时不限制关卡，否则玩家可进入该关时允许购买。解锁条件本身不赠送等级，也不扣除额外费用，第一次升级按 `costs[0]` 购买。前置节点必须属于同一设施且在更早的层，避免循环；没有前置的节点放在首层。

## 支持的战斗属性

属性目录位于 `Content/config/upgrade-attributes.json`，游戏与编辑器共用其标识、名称、基础值和范围；游戏中另有配置失效时使用的保底目录与安全上限。编辑器通过只读接口加载属性目录。

| 属性 ID | 含义 |
| --- | --- |
| `arrow_damage` | 箭矢基础伤害 |
| `fire_rate` | 基础射击间隔的倍率，越小越快 |
| `multi_shot` | 每次齐射箭数 |
| `wall_health` | 城墙生命上限 |
| `heavy_strike` | 箭矢击退距离 |
| `precision` | 暴击概率，0.12 表示 12% |
| `mana_flow` | 每秒额外法力恢复 |
| `wall_armor` | 城墙护甲 |
| `spell_efficiency` | 法术耗蓝倍率，越小越省蓝 |

效果支持三种计算方式：

- `set`：设置该属性的基础成长曲线。一个属性最多一个 `set` 效果；删除后回到属性目录的基础值。
- `add`：增加数值。未升级值必须为 0，避免未购买就获得加成。负值可用于代价或权衡。
- `multiply`：乘以倍率。未升级值必须为 1，各级倍率须大于 0。

最终属性为 **（基础值 + 所有 add 加值）× 所有 multiply 倍率**，最后限制在属性的安全范围内；生命、伤害、箭数等整数接口沿用取整。该计算顺序不受节点在文件中的排列顺序影响。游戏内图标根据节点的首个效果属性绘制，复合效果按行展示。

可以用这些属性组合任意数量的成长节点。新增穿透、召唤、连锁攻击等全新机制，仍需先实现相应战斗逻辑并注册属性；四种主动法术继续使用已有施放逻辑，法术研习页不创建新的施法类型。

## 验证与排查

`UpgradeCatalog.cpp` 是游戏节点解析与效果计算入口。错误配置不会部分写入运行时目录，会记录 `[Progression][Research]` 日志并保留保底目录。工具保存前做输入检查，文件接口继续使用版本比对与原子写入。

`UpgradeCatalogTest.cpp` 覆盖旧格式、任意 ID、多前置 AND 门槛、独立等级、关卡限制、不满足时不扣款、重复/缺失/越界前置、复合效果、空目录及无效配置；`Tests/fixtures/editor-upgrades.json` 是通过浏览器实际新增和保存的配置样例。`Tests/fixtures/editor-multi-prerequisites.json` 是通过浏览器保存的多前置配置，同时覆盖升级节点与主动法术的运行时解析。测试程序只运行规则测试，不进入游戏窗口。

`Tests/fixtures/editor-shared-trees.json` 由浏览器分别在三个设施中编辑保存，覆盖同层四节点均分、双前置、等级与效果增删和关卡门槛；同一份文件交给游戏解析并验证购买及属性计算。`Tests/fixtures/legacy-defense-tree.json` 同时用于工具与游戏的兼容测试，确认旧城防布局转换一致且不改变数值。

## 跨层级连线

游戏与配置工具共用 `Source/TreeConnectionRouter.cpp`：将节点与文字边界作为障碍，在空白通道中寻找直角折线路径。采用“派生合并、接入拆分”：同一父节点的多个分支可共用出线主干，不同来源的线路保持独立；多项前置分别接入目标边缘的不同位置。

相邻层之间统一选择横向高度基准，默认位于两层中央，遇到文字障碍时一起调整。同父分支可合并，不同来源即使同高也保持独立线段和入口；多前置入口之间的空隙不会补成贯通横线。跨层线的引出与接入横线分别对齐对应的层间高度，中段继续避障。入口按来源位置排序，同一配表仅调整前置列表顺序不会改变入口。游戏中每棵树独立规划并缓存线路，避障范围限制在当前树内，标题也参与避障。

节点下方有名称时，允许从侧边短距离引出。拥挤或没有完整层间通道时，退回独立避障线路，保留全部依赖；接入拆分规则继续生效。入口仅影响绘制，不新增技能树节点，也不改变层级、前置的 AND 逻辑或存档。

固定节点位置可能包含无法完全错开的密集依赖；此时仍避开全部节点和文字，在无法绕开的线段交汇处留出断口，两条线不会画成连接点。节点圆形之间的连接不经过其他节点中心，布局坐标与解锁条件不被修改。

工具按实际画布像素计算，调整窗口尺寸后重新规划，避免 SVG 缩放导致连线穿入节点。浏览器使用 `TreeConnectionRouterWeb.cpp` 适配，服务通过 `build_tree_router.py` 将同一 C++ 实现编译并缓存到临时目录；仓库只保留源码。游戏面板缓存几何结果，购买后只要节点与文字边界不变就直接复用路径。新增 `TreeConnectionRouterTest.cpp` 与工具的 `test_tree_routing.cjs` 验证避障、多前置交汇、反向连线及密集依赖。

同层 4 个子节点中，一个同时依赖力量、敏捷时，力量的分支保持共用主干，敏捷的线路与其分开，两路分别进入新节点。测试检查不同来源不会重叠成同一段线，覆盖双/三前置、跨层、横向升级链和前置顺序调整。工具“重新载入”同时刷新页面脚本与连线模块，避免已打开的窗口继续使用更新前的算法。

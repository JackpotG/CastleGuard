# 02 学习路线图

> 总原则：**同一个游戏设计，三个引擎各做一遍**。第二站起不用再想"做什么"，全部注意力放在"这个引擎怎么做"。

## 第一站：Axmol（Cocos2d-x C++ 裸引擎）× 微信小游戏（WASM 适配）

> 2026-11-13 变更：弃用 Cocos Creator 图形化开发，改纯 C++ 代码开发，强化"引擎与渲染原理"学习目标；上架走 WASM 通用适配方案。

**目标**：学完"完整的游戏开发流程"，并借裸引擎深入渲染管线与引擎原理。

| 学习内容 | 说明 |
|----------|------|
| C++ + 场景树/节点模型 | cocos2d-x 经典节点继承体系（Scene/Layer/Sprite），与第二站 Unity 组件化形成对照学习 |
| 通用游戏技术 | 对象池、碰撞、动画状态机、资源分包 |
| 渲染入门 → 进阶 | draw call、合批、图集；引擎源码全开放，读渲染器实现（RenderCommand 生成与合批、多后端抽象） |
| 发布全流程 | WASM 适配转换、备案、实名认证、防沉迷、广告接入——独立开发者最缺的一课 |

**里程碑**
- M0：战斗原型手感确认（真机搓射箭手感）
- M1：MVP 完整可玩（5 关数值验证）
- M2：三选一系统 + 排行榜 + 激励视频接入
- M3：上线，种子用户测试（看次留、第 3 关流失率）

**通过条件**：小游戏真实上线 → 才准开 Unity。

## 第二站：Unity × 移动端 App（重做同一游戏）

设计文档、数值表、玩法现成，专注体会引擎差异：

- C# 与更成熟的组件架构、Prefab 体系
- URP 管线、Shader Graph：**渲染学习发力点**——给箭矢写拖尾 Shader、给技能写溶解/冰冻材质
- Unity 2D 工具链与安卓/iOS 出包，体验与小游戏完全不同的发布链路
- 资产管线对比：同一套 Spine 动画、图集在两个引擎里怎么组织

**通过条件**：安卓包可装可玩，含至少 2 个自写 Shader 效果。

## 第三站：Unreal Engine × 3D 精神续作（不是移植）

UE 做 2D 塔防是大炮打蚊子（Paper2D 基本无人维护）。正确做法：保留核心规则（守点、波次、技能、养成），做成 3D 俯视角或第一人称守城游戏。

- 材质系统、光照、后处理——渲染深水区
- 蓝图 → C++ 渐进路径
- 场景管理、LOD、Nanite/Lumen 等现代管线概念

**通过条件**：一个可玩的 3D 守城 Demo（哪怕只有一关）。

## 渲染学习专项路径

引擎用得熟 ≠ 懂渲染。每站必须完成对应的主动动作：

1. **Cocos 阶段**：搞懂箭矢多了为什么卡（draw call、合批、纹理切换）
2. **Unity 阶段**：Shader Graph 做效果 → 把生成的 Shader 代码读一遍 → 手写两个 HLSL 小效果
3. **UE 阶段**：读材质编辑器背后的 PBR 逻辑，用 Frame Debugger 抓一帧，理解 GBuffer、延迟渲染
4. **理论补充**（有余力）：Games101 公开课 +《Real-Time Rendering》，与工程实践互相印证

## 防烂尾机制

- 同一时间只碰一个引擎，里程碑未达不开新坑
- 每个引擎版本先复刻 MVP，再谈加料
- 每站以真实发布为终点
- 素材做成引擎无关中间格式（数值表用表格/JSON，美术源文件统一归档），跨引擎复用

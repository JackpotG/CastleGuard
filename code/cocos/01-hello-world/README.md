# 第 1 课：Hello World —— 一个游戏的诞生

> 对应开发清单 M0 第一项「环境搭建」。本课目标：不用编辑器摆任何内容，
> 纯代码让屏幕出现文字并动起来，同时建立游戏引擎的心智模型。

## 本课概念地图

```
游戏引擎在做什么？一句话：

    每秒 60 次，重复执行：读取输入 → 更新世界状态 → 把世界画到屏幕上

Cocos 引擎的四个核心角色：

    Director（导演）  全局唯一。驱动游戏循环，负责场景的加载与切换。
    Scene（场景）     一棵节点树的根。一个游戏可以有多个场景
                      （战斗场景、主城场景、结算场景……）。
    Node（节点）      树上的格子。本身不可见，只有位置/旋转/缩放/父子关系。
    Component（组件） 挂在节点上的能力单元。Label 让节点会写字，
                      Sprite 让节点会画图，你写的脚本让节点"有行为"。

    脚本组件的两个生命周期钩子：
      start()      出生时调用一次 → 初始化
      update(dt)   每帧调用一次   → 游戏循环里属于你的那一格
```

## 为什么不是"完全抛开 Cocos Creator"？

Cocos Creator = Cocos 引擎（运行时）+ 编辑器（可视化前端）。
你写的每一行代码（`new Node`、`addComponent`、`update`）调用的就是引擎本体，
编辑器只是同一套数据的图形化视图。真正"裸用引擎"（cocos2d-x/cocos2d-js）
在 2026 年已无法现实地发布微信小游戏——发布管线、小游戏适配层都在 Creator 里。

所以本项目的开发方式定为：

- **游戏内容 100% 用代码构建**（节点、UI、动画、逻辑全部手写）——这是学习主线
- **编辑器只承担两件事**：一次性项目脚手架、构建发布（后者可用命令行替代，
  见下「命令行构建」）
- 场景文件本质是 JSON（节点树 + 组件引用的序列化）。建议建完项目后
  用文本编辑器打开 `assets/main.scene` 看一眼，理解"编辑器只是 JSON 的视图"

## 环境搭建步骤（对应清单第一项）

1. 安装 **Cocos Dashboard**（https://www.cocos.com/），用它安装
   **Cocos Creator 3.8.x LTS**（教程与社区问答生态最完整的版本）
2. 安装 **微信开发者工具**（稳定版即可），并在 Creator 的
   偏好设置 → 程序管理器里指向它的路径
3. Dashboard 新建项目，模板选 **Empty (2D)**，路径建议：
   `CastleGuard/code/cocos/defender/`（整个第一站都在这个项目里做）
4. 把本目录的 `HelloWorld.ts` 复制到项目的 `assets/scripts/` 下
5. 唯一一次编辑器操作：打开自带的 `main` 场景，选中 Canvas 节点，
   属性检查器 → 添加组件 → HelloWorld
6. 点编辑器上方的预览（浏览器运行）：应看到白色文字在屏幕中央摇摆，
   控制台每秒打印一次 dt
7. 构建发布 → 微信小游戏 → 构建，用微信开发者工具打开
   `build/wechatgame` 目录，模拟器跑通后扫码真机预览

### 命令行构建（可选，替代第 7 步的 GUI）

```
# Windows
CocosCreator.exe --project <项目路径> --build configPath=<构建配置.json>
# macOS
/Applications/Cocos/Creator/3.8.x/CocosCreator.app/Contents/MacOS/CocosCreator \
  --project <项目路径> --build configPath=<构建配置.json>
```

构建配置 JSON 先在构建发布面板配好一次后用"导出"功能生成。
注意：命令行构建成功时进程退出码是 36，不是 0。
